# OTA Publishing Guide

How to release a new firmware version so devices can update themselves over-the-air.

## How OTA Works

The device fetches the list of `.bin` files at:

```
https://api.github.com/repos/js9467/cancontroller/contents/versions
```

It looks for files named `bronco_vX.Y.Z.bin`, parses the version numbers, finds the
highest one, and compares it to its own `APP_VERSION`.  If GitHub has a newer version
the device downloads and installs it directly from:

```
https://raw.githubusercontent.com/js9467/cancontroller/master/versions/bronco_vX.Y.Z.bin
```

No intermediate server is involved.  Fly.dev is used only for image optimization.

## Publishing a Release (step-by-step)

### 1. Bump the version

Edit `.version_state.json` at the repo root:

```json
{
  "major": 6,
  "minor": 4,
  "build": 7
}
```

Increment **build** for bug fixes, **minor** for new features, **major** for breaking changes.

### 2. Build the firmware

```powershell
pio run -e waveshare_7in
```

The `tools/versioning.py` pre-build script reads `.version_state.json` and bakes the
version string into `src/version_auto.h` automatically.

Verify the version in the build output:

```
[Versioning] Building version 6.4.7
...
======================== [SUCCESS] ...
```

### 3. Copy the binary to master-wt

```powershell
Copy-Item .pio\build\waveshare_7in\firmware.bin `
    ..\master-wt\versions\bronco_v6.4.7.bin -Force
```

Replace `6.4.7` with the actual version you built.

### 4. Commit and push both repos

**Bronco-Controls-4** (source + version state):

```powershell
git add .version_state.json src/version_auto.h
git commit -m "v6.4.7: <brief description of changes>"
git push origin main
```

**master-wt** (binary store — the OTA source):

```powershell
cd ..\master-wt
git add versions\bronco_v6.4.7.bin
git commit -m "v6.4.7: <same description>"
git push origin master
```

### 5. Verify the release is visible

```powershell
Invoke-RestMethod `
  "https://api.github.com/repos/js9467/cancontroller/contents/versions" |
  Select-Object -ExpandProperty name | Where-Object { $_ -like "*.bin" } |
  Sort-Object
```

You should see `bronco_v6.4.7.bin` in the list.

## Triggering an OTA Update on the Device

From the device web UI (any browser on the same Wi-Fi):

1. Navigate to the device IP → **Settings → OTA Update**
2. Click **Check for Updates** — the device queries GitHub and shows the latest available version
3. Click **Install** next to the version you want
4. The device downloads, flashes, and reboots automatically (~60 seconds)

Or via the API directly:

```bash
# Check what's available
curl http://<device-ip>/api/ota/github/versions

# Install a specific version
curl -X POST http://<device-ip>/api/ota/github/install \
     -H "Content-Type: application/json" \
     -d '{"version":"6.4.7"}'

# Install latest (auto-selects highest version)
curl -X POST http://<device-ip>/api/ota/update
```

## Files Involved

| File | Purpose | Edit? |
|------|---------|-------|
| `.version_state.json` | Single source of truth for version | ✅ Bump before each release |
| `src/version_auto.h` | Generated header with version string | ❌ Auto-generated by build |
| `tools/versioning.py` | Pre-build script that reads state and writes header | ❌ Don't modify |
| `..\master-wt\versions\bronco_vX.Y.Z.bin` | Binary published for OTA | ✅ Copy after each build |

## Troubleshooting

**Device says "up-to-date" but you just published a new version**

- Make sure the `master-wt` push completed — GitHub sometimes takes ~30 s to index
- Confirm the file is visible via the API call above
- Confirm the version in the `.bin` filename matches exactly what was built (`APP_VERSION`)

**OTA download fails mid-way**

- Device must have a stable Wi-Fi STA connection (not just AP mode)
- Check the serial monitor for `[OTA]` lines for the specific HTTP error code

**Wrong version baked into firmware**

- Always build AFTER editing `.version_state.json`
- Never manually edit `src/version_auto.h` — it is overwritten on every build
