# AI Agent Instructions for Bronco Controls Project

## CRITICAL: Version Management Rules

**ALL AI AGENTS MUST FOLLOW THESE RULES - NO EXCEPTIONS**

### 1. NEVER Manually Edit These Files:
- `src/version_auto.h` — auto-generated at build time by `tools/versioning.py`; any manual edit will be overwritten on next build

### 2. Release Workflow

For ANY code changes that need a firmware release:

1. Increment `.version_state.json` (this is the single source of truth)
2. Build: `pio run -e waveshare_7in`
3. Copy binary: `.pio\build\waveshare_7in\firmware.bin` → `..\master-wt\versions\bronco_vX.Y.Z.bin`
4. Commit `Bronco-Controls-4` repo
5. Commit and push `master-wt` repo

See **OTA_PUBLISHING.md** for the complete checklist.

### 3. OTA Update System

OTA is **GitHub-only**. Devices query:
```
https://api.github.com/repos/js9467/cancontroller/contents/versions
```
Find the highest `bronco_vX.Y.Z.bin`, compare to current version, and download from GitHub raw.

No manifest files. No Fly.io OTA server. Just binary files in `master-wt/versions/`.

### 4. Workflow for Code Changes

1. Make code changes to source files
2. Test locally: `pio run -e waveshare_7in`
3. Follow the release workflow above if shipping to devices

### 5. Emergency: Manually Set Version

If the build system cannot run and you must hardcode the version, edit `src/version_auto.h` like this (format is strict):

```cpp
#pragma once
// Auto-generated on YYYY-MM-DDTHH:MM:SS.FFFFFFZ
constexpr const char* APP_VERSION = "X.Y.Z";
```

Then run `pio run -e waveshare_7in` as soon as possible to let the build system re-generate it properly.

### 6. OTA Update Process

After deployment, trigger update on device:

```powershell
# Check current version
Invoke-RestMethod -Uri "http://192.168.7.116/api/status" | Select firmware_version

# Trigger OTA update
Invoke-RestMethod -Uri "http://192.168.7.116/api/ota/update" -Method POST

# Wait 60 seconds, then verify
Start-Sleep -Seconds 60
Invoke-RestMethod -Uri "http://192.168.7.116/api/status" | Select firmware_version
```

### 7. USB Upload (If OTA Fails)

```powershell
# Find COM port (check Device Manager)
[System.IO.Ports.SerialPort]::GetPortNames()

# Upload
pio run -e waveshare_7in --target upload --upload-port COMX
```

### 8. Common Mistakes to Avoid

❌ **DON'T:**
- Edit `version_auto.h` directly (gets overwritten on next build)
- Commit version changes without running a build first
- Push firmware without copying the bin to `master-wt/versions/`
- Skip committing `master-wt` after adding the new binary

✅ **DO:**
- Increment `.version_state.json` before building
- Always build and verify `[Versioning] Building version X.Y.Z` in output
- Copy `.pio/build/waveshare_7in/firmware.bin` to `master-wt/versions/bronco_vX.Y.Z.bin`
- Push both repos

### 10. Debugging OTA Issues

1. **Check versions on GitHub:**
   ```powershell
   Invoke-RestMethod 'https://api.github.com/repos/js9467/cancontroller/contents/versions' | Select -ExpandProperty name
   ```

2. **Confirm device version:**
   ```powershell
   Invoke-RestMethod 'http://192.168.7.116/api/status' | Select firmware_version
   ```

3. **If device doesn't update:** Ensure the GitHub version is strictly higher than the device version. See OTA_PUBLISHING.md.

- GitHub has the latest binary for OTA
